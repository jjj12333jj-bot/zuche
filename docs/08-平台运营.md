# 08 · 平台运营（订单 / 用户 / 网点 / 评价）

> 对应菜单：`平台管理` 下的订单管理、用户管理、网点管理、评价管理。
> 这四页的共同点：**平台是「裁判」不是「运动员」**——能看到全部数据，
> 但尽量不替网点干活；每个破坏性操作都有一条明确的边界。

---

## 1. 为什么是这四页

车辆资产（07）回答"我们有什么车"，这四页回答"谁在租、租得怎么样、哪个网点在赚钱、客户怎么评价"。
四页构成一条完整的运营闭环：

```
网点管理（在哪做生意）
   ↓ 车与单归属
订单管理（生意做得怎么样）
   ↓ 产生
评价管理（客户满意吗） ← 用户管理（谁在租，信用如何）
```

因此它们的共同约束是**归属**：订单、车辆、评价都挂在网点或用户上，
删掉任何一端都会留下孤儿数据。这是本批所有拦截规则的出发点。

## 2. 四条硬规则

### 2.1 订单只能关，不能改

平台端只有一个破坏性动作：**关闭订单**。
- 只对 `WAIT_PAY`（待支付）/ `WAIT_PICKUP`（待取车）开放
- 已取车的单一律拒绝：`订单当前为「已取车/在租」，只能关闭待支付或待取车的订单；已取车的订单请由网点走归还流程`
- 关闭已支付的单会自动**全额退款**（租金 + 押金两笔，分别回指原支付流水）并**释放车辆**

为什么不让平台直接改状态：已取车的单涉及押金、违约金、里程、车况四个结算依据，
平台跳过归还流程关单，这四样就都没有落账，事后查不清是谁的责任。

关闭原因**必填**，落在 `lease_order.cancel_reason`，前缀 `平台关闭：`。
后台关单是"有理由的破坏性操作"，事后复盘只能靠这句话。

### 2.2 冻结必须当场生效

JWT 是无状态的，签出去就收不回来。只改 `sys_user.status`，用户手里的旧 token
仍能用到过期（默认 7 天），等于冻结没生效。

做法：`AccountStatusGuard` 在 `JwtInterceptor` 里核对一次账号状态，
结果按 userId 缓存 **60 秒**；冻结/解冻时业务侧主动 `evict()`，同实例立刻失效，
多实例最多延迟 60 秒。

```java
// JwtInterceptor
LoginUser user = jwtUtil.parse(token);
if (accountStatusGuard.isDisabled(user.getUserId())) {
    writeUnauthorized(response, "账号已被冻结，请联系平台客服");
    return false;
}
```

为什么**不**把 status 写进 JWT：写进去就固化了，冻结要等 token 过期，跟不做一样。

冻结还有两条自我保护：
- 不能冻结当前登录账号（否则把自己锁在系统外面）
- 不能冻结最后一个可用的系统管理员（否则没人能管理系统）

### 2.3 调分只有一个入口

`sys_user.credit_score` 不允许任何业务直接 update，必须走 `CreditService.adjustByAdmin`，
它在一个事务里做三件事：写 `credit_log`（`change_type = ADMIN`）→ 回写分数 → 重算等级。

保证这条恒等式永远成立：

```
credit_score == clamp(100 + Σ credit_log.score_change, 0, 150)
```

调分单次限制 **-50 ~ +50**，原因必填且最多 200 字。
后台改完分数，「信用明细」里能查到这次操作和操作人。

### 2.4 网点能停用，不轻易删除

- **删除**：只有「零车辆 + 零订单」的网点可以删，用来清理建错的空网点
- 有车或有单时拒绝，并把数量报出来：
  `该网点下还有 6 台车、79 笔订单，不能删除；请先把车辆调走或下架，或改为「停用营业」`
- **停用**：有进行中订单（待取车 / 在租 / 逾期）时拒绝停用——
  客户已经付了钱约好来取车，店却关了门，只能由客服逐个打电话道歉

网点表**不存 vehicle_count**：车辆数随调车实时变化，冗余字段必然不一致，
一律用标量子查询现算。

## 3. 四个页面各做什么

### 3.1 订单管理 `/admin/orders`

- 全平台订单，可按状态、网点、取车日期区间、订单号/客户/手机号筛选
- 顶部 6 个数字卡：总数 300 / 待取车 12 / 在租 12 / 逾期 6 / 今日新增 12 / 已结算违约金 ¥7,188.48
- 详情抽屉：基础信息 + 车辆明细 + 支付流水 + 退款流水
- 违约金：未结算的单显示"按当前规则算出的预估"，结算后才显示实际扣款
- 押金减免：`实付押金 ÷ 系数` 反推出"没有信用折扣要交多少"，差额即减免额

### 3.2 用户管理 `/admin/users`

- 9 个账号：1 系统管理员 / 2 网点管理员 / 6 普通用户
- 表格带角色、归属网点、信用分与等级配色、订单数与完成数、累计消费、进行中订单
- 三个动作：调分（弹窗带分数预览）、冻结/解冻、跳转信用明细
- 累计消费口径：`status NOT IN ('CANCELLED','WAIT_PAY')` 的 `total_amount` 之和
  ——待支付是没到账的钱，已取消是不存在的钱

### 3.3 网点管理 `/admin/stores`

- 4 个网点，每个 6 台车
- 表格带车辆分布（可租 / 在租 / 维保三个色块）、订单数、进行中订单数、本月订单额
- 新增/编辑：编码唯一且 2~10 位大写字母或数字；电话支持座机与手机两种格式
- 负责人从「网点管理员」角色里选，也可以不指定

### 3.4 评价管理 `/admin/evaluations`

- 12 条种子评价，综合 4.25 分（车况 4.25 / 服务 3.75），5 星 6 条 / 4 星 3 条 / 3 星及以下 3 条
- **双维度评分**：`vehicle_rating`（车况）与 `store_rating`（服务）分开打，
  `rating` 是两者平均，只用于统计与排序。分成两项是因为「车好但服务差」和
  「车旧但服务好」对运营意味着完全不同的动作——一个要整备车辆，一个要培训店员
- **两级处置**：`status=0` 隐藏（随时可恢复，后台照常可查）、`deleted=1` 删除
  （仅系统管理员，针对辱骂/广告/泄露隐私，走逻辑删除留痕）
- 回复覆盖式：第一条写错了可以直接改，不必再发一条把对话搞乱
- 图片列存 JSON 数组，用 `JsonStringListTypeHandler` 解析成 `List<String>`，
  解析失败返回空集合而不是抛异常——一条脏数据不该让整个列表打不开

**权限边界（这一块最容易做错）**：

| 角色 | 看 | 回复 | 隐藏 | 删除 |
|---|---|---|---|---|
| 普通用户 | 车辆详情页看脱敏评价 | ✗ | ✗ | ✗ |
| 网点管理员 | 仅本网点 | ✓ 解释性回复 | ✗ | ✗ |
| 系统管理员 | 全平台 | ✓ | ✓ | ✓ |

让商家删自家差评，等于既当运动员又当裁判——差评一消失，评分就没人信了。

## 5. 验证步骤

```bash
# 0) 取 token
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}' | jq -r .data.token)

# 1) 四组统计
curl -s http://localhost:8080/api/admin/orders/stats       -H "Authorization: Bearer $TOKEN"
# 期望：total 300 / pendingPickup 12 / inUse 12 / overdue 6 / lateFeeTotal 7188.48
curl -s http://localhost:8080/api/admin/evaluations/stats  -H "Authorization: Bearer $TOKEN"
# 期望：total 12 / avgRating 4.25 / fiveStar 6 / lowStar 3 / replied 5 / unreplied 7
curl -s http://localhost:8080/api/admin/users/stats        -H "Authorization: Bearer $TOKEN"
# 期望：total 9 / normal 9 / frozen 0 / customers 6 / storeAdmins 2
curl -s http://localhost:8080/api/admin/stores/stats       -H "Authorization: Bearer $TOKEN"
# 期望：total 4 / vehicleTotal 24

# 2) 关闭已完成订单 → 拒绝
curl -s -X POST http://localhost:8080/api/admin/orders/<已完成订单ID>/close \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"reason":"测试"}'
# 期望：code 1001，提示「只能关闭待支付或待取车的订单」

# 3) 冻结自己 → 拒绝
curl -s -X PUT http://localhost:8080/api/admin/users/1/status \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"status":0}'
# 期望：code 1001，「不能冻结当前登录账号」

# 4) 冻结后旧 token 立即失效
#    a. 用 user6 登录拿 token U
#    b. 用 admin 冻结 user6（id=9）
#    c. 用 token U 请求 /api/orders → 期望 401「账号已被冻结，请联系平台客服」

# 5) 删除有车的网点 → 拒绝
curl -s -X DELETE http://localhost:8080/api/admin/stores/1 -H "Authorization: Bearer $TOKEN"
# 期望：code 1001，「该网点下还有 6 台车、79 笔订单」

# 6) 停用有活跃单的网点 → 拒绝
curl -s -X PUT http://localhost:8080/api/admin/stores/1/status \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"status":0}'
# 期望：code 1001，「还有 6 笔进行中的订单」
```

> 注意：2/3/5/6 都是**只读拦截**，不会改数据；
> 但「关闭订单」和「冻结用户」会真的改库，测完请重跑 `01-schema.sql` + `02-seed.sql` 复位。

## 6. 本批踩到的坑

| 现象 | 根因 | 修法 |
|---|---|---|
| 评价列表 `images` 恒为 null | TEXT 里的 JSON 数组直接映射 `List<String>` 类型不匹配，MyBatis **静默丢值不报错** | 写 `JsonStringListTypeHandler`，`resultMap` 里显式挂上，`autoMapping=true` 保其余列 |
| 评价图片全是空 | seed 没写 `images` 列 | 用 `JSON_ARRAY(m.cover_image)` 现取车型图，前 5 条单图、6~10 条双图、最后 2 条留空验证空态 |
| 用户列表「最近登录」全是「从未登录」 | `last_login_time` 字段建了但登录时从没写 | 登录成功后 `updateById` 写一次；seed 里给演示账号补历史登录时间 |
| 网点列表排序报错 | 我按惯性写了 `ORDER BY s.sort_no`，但 `store` 表没有这个字段 | 改成 `status DESC, id` |

## 7. 已知边界

- 平台不能代网点办取车/还车，只能关单——履约责任人必须唯一
- 评价没有「删除」接口，只有隐藏
- 网点经纬度仅存储，不接入地图服务
- `operation_log` 表仍未接入 AOP 切面，本批写操作靠 `cancel_reason` / `credit_log` 留痕；
  统一的日志切面与查询页在批次三做
