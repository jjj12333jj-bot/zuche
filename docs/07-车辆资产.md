# 07 · 车辆资产（平台端）

> 对应菜单：`/admin/vehicle` 目录下的 5 个页面 —— 品牌管理、车型管理、车辆档案、保养维修、保险记录。
> 权限：`SYS_ADMIN`，控制器统一挂 `@RequireRole(RoleCode.SYS_ADMIN)`。

## 1. 为什么这 5 个页面绑在一起

它们是同一条资产链路上的四层：**品牌 → 车型 → 车辆 → 台账（保养/保险）**。

- 品牌和车型决定「这台车是什么、指导价多少」；
- 车辆档案决定「这台车现在在哪个网点、多少钱、能不能租」；
- 保养与保险决定「这台车还能不能租、敢不敢租」。

拆成 5 个互不相干的 CRUD 会出现「车型停用了但车还在卖」「保险过期两个月车还在租」这类问题，
所以这 5 个页面共用一套服务与同一条校验规则。

## 2. 三条硬规则

### 2.1 停用可以，删除要拦

| 操作 | 规则 | 拒绝文案 |
|---|---|---|
| 停用品牌/车型 | 允许，提示影响面 | 「已停用，该品牌下 9 台车将不再出现在前台车辆列表」 |
| 删除品牌 | 旗下有车型则拒绝 | 「该品牌下还有 4 个车型，请先停用或删除车型」 |
| 删除车型 | 旗下有车辆则拒绝 | 「该车型下还有 1 台车，请先停用或删除车辆档案」 |

停用只是不再对外展示，历史订单仍查得到；删除是逻辑删除（`deleted=1`），
`order_item` 仍指向这台车，订单详情不会因为删了车就查不出东西。

### 2.2 有未结束订单的车，三件事不能做

未结束订单 = `WAIT_PAY / WAIT_PICKUP / IN_USE / WAIT_RETURN / OVERDUE` 五种状态之一。

- 不能改车型（`modelId`）
- 不能改归属网点（`storeId`）
- 不能改可用状态（`status`）

原因：订单结账用的是「下单时的网点 + 车型快照」。中途把车调到别家网点，
账单上的门店和实际交车的门店就对不上了。

校验点不只是前端置灰，接口里也会再查一次 `countActiveOrdersOfVehicle`——
前端可能停留在旧数据上，人点下去的时候订单刚成立。

### 2.3 车辆的品牌永远由车型反查

`VehicleSaveDTO` 里**没有** `brandId` 字段。建档时按 `modelId` 查出车型，
把 `model.brandId` 写进车辆。

允许单独填品牌，必然会出现「车型是朗逸、品牌填了丰田」的脏数据，
而这种脏数据在按品牌统计资产时会直接算错。

## 3. 五个页面各做什么

### 3.1 品牌管理 `/admin/vehicle/brands`

- 列表带 **车型数 / 车辆总数 / 其中可租**，停用前一眼看清波及面
- 顶部数字卡走全量统计接口，不是当前页 10 条算出来的
- 重名校验：品牌名唯一

### 3.2 车型管理 `/admin/vehicle/models`

- 列表带 **车辆数** 与 **在库最低日租金**
- 最低价 ≠ 指导价时标橙提示 —— 说明有人单独给车调过价，
  这是「车型写着 129、实际在租 199」的唯一发现途径
- 同品牌下车型名唯一

### 3.3 车辆档案 `/admin/vehicle/list`

- 跨网点，可按网点/品牌/状态筛选，支持车牌、编号、VIN、车型模糊搜
- 每行显示 **当前占用订单号与租期**、**保单到期日**、**下次保养日**
- 操作分「详情 / 编辑 / 状态」三档：状态用下拉，避免三个按钮挤在一格
- 详情抽屉分四块：资产信息、经营数据（出租次数/浏览量）、合规与维保、当前占用订单

车牌校验：`^\p{Han}[A-Z]·?[A-Z0-9]{4,6}$`，兼容 `闽C12345` 与种子数据的 `闽C·1234`。

### 3.4 保养维修 `/admin/vehicle/maintenance`

台账**只增不改**（没有编辑与删除接口）。写错了补一条更正记录，而不是抹掉历史。

登记时两个连带动作：

1. 进场里程 > 车辆档案里程 → 自动把车辆里程往前推（台账是里程的唯一可信来源）
2. 登记「维修」且车辆当前可租、又没有未结束订单 → 自动置为维保中

第 2 条是防事故的：维修中的车还能被下单，是真实的业务事故。

### 3.5 保险记录 `/admin/vehicle/insurance`

- 到期天数由 SQL `DATEDIFF(end_date, CURDATE())` 算，前端不做日期减法
- 三档呈现：**已过期（红）/ 30 天内到期（橙）/ 生效中（绿）**
- 同车同险种时段不允许交叉，首尾相接（旧单到期当天新单生效）允许
- 「只看 30 天内到期」开关，一键拉出待续保清单

种子数据刻意留了 **2 张已过期未续 + 6 张 30 天内到期**（车 23/24 已过期，车 1–6 临期），
否则这个页面的预警能力演示不出来。

## 4. 接口清单

统一前缀 `/api/admin/vehicle`，全部要求 `SYS_ADMIN`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/stats` | 品牌/台账/保单三组全量统计 |
| GET | `/brands` | 品牌分页（带车型数、车辆数、可租数） |
| GET | `/brands/options` | 启用品牌下拉 |
| POST | `/brands` | 新增品牌 |
| PUT | `/brands/{id}` | 编辑品牌 |
| PUT | `/brands/{id}/status` | 启停品牌 |
| DELETE | `/brands/{id}` | 删除品牌（有车型则拒绝） |
| GET | `/models` | 车型分页（带车辆数、在库最低价） |
| GET | `/models/options` | 启用车型下拉（可按品牌过滤） |
| POST/PUT/DELETE | `/models`、`/models/{id}` | 车型增改删 |
| PUT | `/models/{id}/status` | 启停车型 |
| GET | `/stores` | 启用网点下拉 |
| GET | `/list` | 车辆档案分页（跨网点） |
| POST/PUT/DELETE | `/list`、`/list/{id}` | 车辆建档 / 编辑 / 删除 |
| PUT | `/list/{id}/status` | 上下架、进维保 |
| GET | `/maintenance` | 台账分页（带车辆与网点） |
| POST | `/maintenance/vehicles/{vehicleId}` | 平台登记台账 |
| GET | `/insurance` | 保单分页（带到期天数） |
| POST/PUT/DELETE | `/insurance`、`/insurance/{id}` | 保单增改删 |

## 5. 验证步骤

```bash
# 1) 列表类：5 个页面数据齐
curl -s 'http://localhost:8080/api/admin/vehicle/stats' -H "Authorization: Bearer $TOKEN"
# 期望：brand{total:9,enabled:9,vehicles:24,rentable:9}
#       maintenance{total:13,maintain:9,repair:4,cost:13800}
#       insurance{total:48,expired:2,soon:6,premium:114600}

# 2) 删除有车型的品牌 → 400
curl -s -X DELETE 'http://localhost:8080/api/admin/vehicle/brands/1' -H "Authorization: Bearer $TOKEN"
# 期望：{"code":400,"message":"该品牌下还有 4 个车型，请先停用或删除车型"}

# 3) 已租出的车改状态 → 400
curl -s -X PUT 'http://localhost:8080/api/admin/vehicle/list/3/status' \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -d '{"status":1}'
# 期望：{"code":400,"message":"该车当前已租出，需等订单归还后才能调整状态"}

# 4) 保险时段重叠 → 400
# 期望：{"code":400,"message":"该车同险种已存在时段重叠的保单，请先核对起止日期"}
```

页面侧预期：

- `/admin/vehicle/brands`：9 个品牌、9 条车型数合计 24、车辆资产合计 24 台
- `/admin/vehicle/models`：24 个车型，朗逸/途观L/ID.4 等在库最低价标橙
- `/admin/vehicle/list`：24 台车，可租 9 / 已租出 12 / 维保 2 / 下架 1
- `/admin/vehicle/maintenance`：13 条台账，保养 9 维修 4
- `/admin/vehicle/insurance`：48 张保单，已过期 2 张红色、30 天内 6 张橙色

## 6. 已知边界

- 车辆图片（`vehicle_image`）不在本批范围，仍由种子生成，后台没有图集管理页
- 违章台账（`vehicle_violation`）表已建，未开放接口
- 保险「生效中」状态按日期自动判定，不支持手工改状态——手工改必然和日期打架
- 台账只增不改是刻意的，若需要更正请在业务上补一条冲销记录
