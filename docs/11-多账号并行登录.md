# 11 · 多账号并行登录（标签页级会话）

> 对应改动：前端登录态存储从 `localStorage` 迁移到 `sessionStorage`，路由守卫支持 `?switch=1` 换号，401 只清本页。
> 目标：系统管理员、网点管理员、多个普通用户可以在同一个浏览器的不同标签页里同时在线，互不覆盖。

---

## 1. 原来的问题

演示时想「一边开管理员看数据、一边用普通用户下单」，只能：

1. 在 A 标签页用 `admin` 登录，看后台；
2. 想用 `user1`，就得在 A 页先退出登录，再登录 `user1`；
3. 此时 A 页已经变成普通用户，管理员那一屏没了。

如果硬开两个标签页：A 页登录 `admin`，B 页再登录 `user1`，A 页的界面**看起来还是管理员**（侧边栏、看板、用户名都没变），但点任何一个管理员功能，后端返回：

```
403 无权访问该接口
```

更迷惑的是：刷新 A 页之后，它直接变成了 `user1` 的身份——说明 A 页的身份早就被换掉了，只是界面没来得及变。

---

## 2. 根因：localStorage 是整个 origin 共享的

原实现把登录态放在 `localStorage`：

```js
// 旧代码
localStorage.setItem('zuche_token', data.token)   // 同一浏览器、同一域名下所有标签页共用这一份
```

`localStorage` 的作用域是 **origin**（协议 + 域名 + 端口），不是标签页。于是：

```
标签页 A（admin）  ──写──┐
                         ├──→ localStorage['zuche_token']  ← 只有一份
标签页 B（user1） ──写──┘         B 登录时被覆盖成 user1 的 token
```

而界面渲染用的是 Pinia 内存里的 `userInfo` —— A 页内存里仍然是 admin，所以「表面没变化」；
但 axios 请求拦截器每次都从 `localStorage` 现取 token，取到的是 user1 的 → 后端按 USER 角色鉴权 → 403。

**一句话**：界面读内存、请求读存储，两套数据源，被跨标签页覆盖后就开始打架。

---

## 3. 方案：登录态下沉到标签页

### 3.1 存储选型

| 方案 | 能否多标签页并行 | 刷新是否掉登录 | 结论 |
|---|---|---|---|
| `localStorage` | ✗ 同源共享，后登录覆盖先登录 | 不掉 | 现状，问题根源 |
| **`sessionStorage`** | ✓ 每个标签页独立一份 | 不掉（同一标签页内刷新仍在） | **采用** |
| 只放内存（Pinia） | ✓ 各自独立 | 掉，刷新即退登 | 体验太差 |
| URL 上带 `?sid=` | ✓ | 不掉 | token 出现在地址栏/日志里，不安全 |
| 每个账号一个浏览器 Profile | ✓ | 不掉 | 要用户开多个浏览器，不可接受 |

`sessionStorage` 的生命周期就是标签页的生命周期：
**刷新不丢、新标签页是全新会话、关掉标签页即失效**——正好是我们要的粒度。

### 3.2 关键改动

新增 `frontend/src/utils/authSession.js`，把「登录态从哪读写」收成一个模块，其余代码只调它：

```js
export function getToken()            // 读当前标签页 token
export function getUser()             // 读当前标签页用户信息
export function saveAuth(data)        // 登录/注册成功：token + 用户信息一起写
export function saveUser(userInfo)    // 只更新用户信息（信用分等实时字段）
export function clearAuth()           // 只清当前标签页
export function openLoginInNewTab()   // 新标签页换号
```

四个调用方同步改掉：

| 文件 | 改动 |
|---|---|
| `store/user.js` | state 初始化、`applyAuth`、`refresh`、`logout` 全部走 `authSession` |
| `utils/request.js` | 请求拦截器取本页 token；401 只清本页并重置内存 store |
| `router/index.js` | 守卫用 `getToken()`；`/login?switch=1` 先清本页身份再展示表单 |
| `layout/*.vue`、`views/login/index.vue` | 新增「新标签页登录其他账号」入口与提示 |

### 3.3 老数据只迁移一次

升级后第一次加载的标签页会把 `localStorage` 里的旧 token 接管到本页，然后**删掉旧键**：

```js
function migrateLegacyOnce() {
  const legacyToken = localStorage.getItem(TOKEN_KEY)
  if (legacyToken && !sessionStorage.getItem(TOKEN_KEY)) {
    sessionStorage.setItem(TOKEN_KEY, legacyToken)
    ...
  }
  localStorage.removeItem(TOKEN_KEY)   // 关键：删掉，避免后开的标签页又捡起来
  localStorage.removeItem(USER_KEY)
}
```

如果只复制不删除，后开的标签页会再「继承」一次 admin 身份，等于没改。

### 3.4 新标签页换号：`?switch=1`

浏览器在 `window.open` / 复制标签页时会**复制一份 sessionStorage** 给新标签页（这是 HTML 规范行为）。所以「新标签页登录其他账号」打开的页面会带着当前账号的身份，直接展示登录表单会让人困惑。

处理办法是给入口加个标记，守卫里先清再放行：

```js
router.beforeEach(async (to) => {
  const userStore = useUserStore()
  if (to.path === '/login' && to.query.switch === '1') {
    userStore.logout()          // 只清本标签页
  }
  const token = getToken()
  ...
})
```

登录页据此显示橙色提示：「正在为当前标签页登录新账号，原标签页的登录状态保持不变」。

### 3.5 401 只影响出事的那个标签页

token 过期时，原实现直接 `localStorage.removeItem`，会把**所有**标签页一起踢下线。现在只清本页，并顺手修了一个老毛病：并发请求同时 401 会弹一串相同的报错、跳多次登录页，加了个 1.5 秒的单飞开关：

```js
let authExpiring = false
function handleAuthExpired(message) {
  clearAuth()
  import('@/store/user').then(({ useUserStore }) => useUserStore().logout())  // 内存也要清
  if (authExpiring) return
  authExpiring = true
  setTimeout(() => { authExpiring = false }, 1500)
  ...
}
```

注意这里用动态 `import` 拿 store：`request.js` 被 `api/auth.js` 引用，`store/user.js` 又引用 `api/auth.js`，静态导入会形成循环依赖。

## 4. 怎么用（演示口径）

```
标签页 1：admin   → /admin/dashboard   看板、智能分析、风控审批
标签页 2：store1  → /store/overview    网点车辆、调度、取还车
标签页 3：user1   → /               下单、支付、信用中心
```

三种开法都行：

1. 浏览器新建标签页 → 输入地址 → 登录另一个账号；
2. 任意页面右上角头像 → **新标签页登录其他账号**（自动清掉继承来的身份）；
3. 复制当前标签页 → 在副本里重新登录（副本从复制那一刻起就是独立会话）。

「退出当前账号」只退出当前标签页的账号，其他标签页继续正常工作。

---

## 5. 取舍与边界

| 现象 | 说明 |
|---|---|
| 新开标签页要重新登录 | 有意为之。要并行多账号，就不能让新标签页自动继承身份 |
| 关掉标签页登录态即失效 | `sessionStorage` 的生命周期如此，也顺带降低了共用电脑的风险 |
| 同一标签页内换号仍需退出 | 一个标签页只承载一个身份 |
| 一个账号可以在多个标签页同时登录 | 后端 JWT 无状态、没有单点登录限制，本来就不阻止 |
| 无法跨标签页同步退出 | 这是隔离的代价；如需「一处退出全部下线」得引入服务端会话表 |
| 服务端没有会话列表 | 想做到「查看/踢掉某台设备的登录」需要 `sys_user_token` 表 + 黑名单，本阶段不做 |

## 6. 验证记录

用 Playwright 在同一个浏览器上下文里开多个标签页（同源、共享 localStorage，等价于真实多开）：

| 用例 | 预期 | 实测 |
|---|---|---|
| A 登录 `admin` | 跳 `/admin/dashboard` | ✅ |
| B 新标签页打开 `/login` | 不继承 A 的登录态 | ✅ token 为空 |
| B 登录 `user1` | 跳 `/`，A 侧仍为管理员 | ✅ 两页 token 不同 |
| A 调 `/api/admin/orders` | 200 | ✅ 操作成功 |
| B 调 `/api/admin/orders` | 403 | ✅ 无权访问该接口 |
| B 调 `/api/orders` | 200 | ✅ |
| A 刷新页面 | 仍是管理员，不被 B 顶掉 | ✅ |
| C 登录 `store1` | 跳 `/store/overview`，网点接口 200、管理员接口 403 | ✅ |
| C 打开 `/login?switch=1` | 本页 token 清空、显示换号提示，A 不受影响 | ✅ |
| B 点「退出当前账号」 | B 回登录页；A 管理员接口仍 200 | ✅ |
