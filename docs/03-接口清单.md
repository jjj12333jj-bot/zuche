# 03 接口清单（草案 v0.3）

> **v0.3 变更（S1 落地后）**：认证新增 `GET /api/auth/menus`（按角色返回菜单树）；
> 登录/注册返回**扁平结构** `{token,userId,username,realName,avatar,roleCode,creditScore,creditLevel,storeId}`，
> 不再包一层 `userInfo`；车辆模块已按真实表结构落地：`/api/vehicles`、`/api/vehicles/options`、`/api/vehicles/{id}`，
> 筛选项由 `sys_dict_data` + `vehicle_brand` + `store` 聚合，`categoryId` 改为 `categoryCode`。

> **v0.2 变更（数据库改为 30 表后）**：`payment` → `payment_record`、`comment` → `order_evaluation`、
> `address` → `user_address`；车型分类改由 `sys_dict_data(dict_type='vehicle_category')` 提供，不再有 `category` 表；
> 车辆拆为 `vehicle_brand / vehicle_model / vehicle`，后台新增品牌、车型、保养、保险、违章五个管理入口；
> 订单支持一单多车，下单入参为 `items[{vehicleId, quantity}]`；新增信用申诉 `/api/credit/appeals` 与风控名单接口。
> 具体接口在 S1-S5 落地时逐条确认，本节清单为范围基线。

> 统一前缀 `/api`；统一返回 `Result<T> { code, message, data, timestamp }`；分页返回 `PageResult<T> { records, total, page, size }`。
> 鉴权：除登录/注册/首页/车辆浏览/公告外，均需 `Authorization: Bearer <token>`。
> 权限：`@RequireRole("USER")` / `("STORE_ADMIN")` / `("SYS_ADMIN")`；标注 `公开` 的接口免登录。
> 约定：`page` 从 1 开始；`size` 默认 10，上限 100。

## 四、租赁订单（order）—— 用户端

> **S2 已实现**（其余为本清单的范围基线，后续阶段落地）。实际路径以本表为准：
> 试算放在 `/api/orders/lease-quote` 而不是 `/api/vehicles/{id}/lease-quote`，
> 因为 `/api/vehicles/**` 是免登录白名单，试算必须拿到当前登录人的信用分，走订单域更合理。

| 方法 | 路径 | 权限 | 说明 | 状态 |
|---|---|---|---|---|
| POST | `/api/orders/lease-quote` | 登录 | **试算**：入参 `vehicleId/startDate/endDate/quantity`，返回租期天数、折后日租金、租金、标准押金、押金系数、应付押金、信用减免、合计、信用快照 | ✅ S2 |
| POST | `/api/orders` | 登录 | 创建订单：金额由后端按库内价格重算；写入信用快照；状态 `WAIT_PAY`（不锁车） | ✅ S2 |
| GET | `/api/orders` | 登录 | 我的订单分页：`status`（空=全部）、`page`、`size`；只返回本人订单 | ✅ S2 |
| GET | `/api/orders/{id}` | 登录 | 详情：车辆明细 + 支付流水 + 信用快照 + 押金减免反推 | ✅ S2 |
| POST | `/api/orders/{id}/pay` | 登录 | **模拟支付**：`WAIT_PAY → WAIT_PICKUP`；生成 RENT + DEPOSIT 两条流水；CAS 锁定车辆 | ✅ S2 |
| POST | `/api/orders/{id}/cancel` | 登录 | 取消：**仅 `WAIT_PAY`**（`WAIT_PICKUP` 需退款+扣分，S3 开放）；释放车辆 | ✅ S2 |
| POST | `/api/orders/{id}/pickup` | 登录 | 确认取车：`WAIT_PICKUP → IN_USE` | S3 |
| POST | `/api/orders/{id}/return-apply` | 登录 | 申请归还：`IN_USE`/`OVERDUE → WAIT_RETURN` | S4 |
| GET | `/api/orders/{id}/payments` | 登录 | 流水查询（S2 已并入详情 `payments` 字段，独立接口按需再加） | S4 |
| POST | `/api/orders/{id}/evaluation` | 登录 | 已完成订单评价（一单一评，车况/服务双维度） | ✅ S7 |

**S2 状态流转实测覆盖**：

| 场景 | 期望 | 实际 |
|---|---|---|
| `WAIT_PAY` → 支付 | 成功，→ `WAIT_PICKUP` | ✅ |
| `WAIT_PICKUP` → 再次支付 | 拒绝「订单已经是待取车」 | ✅ |
| `CANCELLED` → 支付 | 拒绝「已取消不能变更为待取车」 | ✅ |
| `WAIT_PICKUP` → 取消 | 拒绝「仅待支付的订单可以取消」 | ✅ |
| 车辆已被他人租出 | 支付时 CAS 失败，整单回滚 | ✅ |
| 未登录 / 越权查他人订单 | 401 / 404 | ✅ |

> 逾期提醒不单独建接口：订单列表/详情返回 `overdue` 布尔、`overdueDays`、`lateFee`、`daysToReturn`，前端展示红色提醒条。

## 八、错误码

| code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数校验失败（返回字段错误明细） |
| 401 | 未登录 / token 失效 |
| 403 | 无权限（角色不符或越权访问他人数据） |
| 404 | 资源不存在 |
| 500 | 系统异常 |
| 1001 | 业务异常（库存不足、状态不允许、信用分不足等），message 直接展示给用户 |

## 九、接口规模与优先级

- 总计约 **78 个**接口（含 CRUD），其中：
  - P0（答辩主线必须）：认证 5、车辆 5、订单 8、信用 6、看板 4、网点订单 4、调车 3；
  - P1（完整性）：其余 CRUD 与内容管理。
- 开发顺序：先 P0 打通一条订单全链路，再补 P1 管理面。
