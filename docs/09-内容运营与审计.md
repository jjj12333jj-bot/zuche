# 09 · 内容运营与审计（公告 / 轮播图 / 操作日志）

> 对应菜单：`平台管理` 下的公告管理、轮播图管理、操作日志。
> 前两页面向「用户看到什么」，第三页面向「我们做过什么」——
> 一个对外发声，一个对内留痕，共同点是**都只由平台管理员操作**。

---

## 1. 为什么是这三页

前面几批做的是「交易」：车、单、钱、评价。这三页做的是「治理」：

```
公告管理  →  规则与通知怎么传达给用户
轮播图管理 →  首页的注意力放在哪里
操作日志  →  后台每一个写操作有没有人负责
```

没有这三页，平台能跑但没有运营手段；出了问题也说不清是谁改的。
尤其操作日志——**答辩时最容易被追问「你怎么证明这个操作是管理员做的」**，
这张表就是答案。

---

## 2. 三条设计决策

### 2.1 公告：草稿 / 发布两态，而不是「有发布时间就是已发布」

表里 `status` 与 `publish_time` 是两个独立字段，不是一个字段的两种解读：

| 场景 | status | publish_time |
|---|---|---|
| 新建（不传状态） | 0 草稿 | NULL |
| 发布 | 1 | 当前时间 |
| 下架 | 0 | **保留原值** |
| 重新发布 | 1 | **刷新为当前时间** |

为什么下架不清空发布时间：运营复盘要回答「这条公告挂了多久」，清空就答不了。
为什么重新发布要刷新：前台按 `publish_time DESC` 排序，刷新即置顶，
不需要额外的「置顶」字段和排序接口。

新建时不传状态**默认草稿**：新写的公告直接推到用户面前，标题打错字或正文没写完，
撤回来比发出去容易得多。

### 2.2 轮播图：能藏不删，排序号自动排末尾

- 「隐藏」是常规动作，删除是例外：活动结束先藏起来，下次换张图还能复用位置
- 新建不填 `sort_no` 时自动取 `MAX(sort_no) + 1`，新图排在该位置最后，不会插队
- `image_url` 只允许 `/` 或 `http(s)://` 开头（`@Pattern`），挡住 `javascript:` 这类地址
- `link_url` 空串在服务层归一成 `null`：前端判断「能不能点」只看是否为 null，两种空值会各写一套

图片存地址不存二进制：演示环境没有对象存储，seed 用 `/images/banners/*.svg` 占位；
以后接 OSS 只换 `image_url` 内容，表结构与接口都不用动。

### 2.3 操作日志：只读，且不允许删

`AdminOperationLogController` 只有 4 个 GET，**没有任何写接口**。
审计日志一旦可以事后编辑，就不再具备审计价值——这条比「方便运维清理」重要。

## 3. AOP 切面：一次注解，两端留痕

### 3.1 切在 Controller，不切 Service

```
请求 → JwtInterceptor → Controller ← 切面在这里
                            ↓
                        Service（@Transactional）
                            ↓
                          事务提交
                            ↓
                       切面 finally 写日志
```

切在 Service 里面会有一个致命问题：Service 方法带 `@Transactional`，
切面若在事务内写日志，业务回滚时日志跟着回滚——**最该留痕的失败操作反而没有记录**。
切在 Controller 外层，事务在 Service 返回时已提交，日志是一次独立写入。

### 3.2 注解即埋点

```java
@PostMapping
@OpLog(module = "公告管理", operation = "新增公告")
public Result<AnnouncementVO> create(@Valid @RequestBody AnnouncementSaveDTO dto) { ... }
```

业务代码里没有任何一行 `log.insert`。新增接口只需加一个注解，
不会出现「这个模块记了那个模块忘了」的半吊子状态。

### 3.3 三个必须处理的细节

**① 失败也要记**

```java
try {
    return joinPoint.proceed();
} catch (Throwable t) {
    success = false;
    throw t;              // 原样抛出，交给全局异常处理器
} finally {
    save(...);            // 成功失败都落库，status 0/1
}
```

**② 参数脱敏 + 截断**

```java
private static final Pattern SENSITIVE = Pattern.compile(
    "(\"[^\"]*(?:password|passwd|token|secret|idcard|bankcard)[^\"]*\"\\s*:\\s*)\"(?:[^\"\\\\]|\\\\.)*\"",
    Pattern.CASE_INSENSITIVE);
// password / token / idCard 等一律替换为 ******，整体截断到 2000 字
```

**③ 日志写失败不能拖垮业务**

`OperationLogService.record()` 内部 try-catch，失败只打 warn。
「关闭订单成功但日志没记上」是审计完整性问题，不是业务故障。

## 4. 三个页面各做什么

### 4.1 公告管理 `/admin/announcements`

- 顶部四卡：总数 / 已发布 / 草稿 / 累计浏览
- 列表不返回正文（TEXT 字段，几条长公告就能把一页响应撑到几百 KB），
  点标题弹「前台预览」，编辑时单独取详情
- 行内动作：编辑 / 发布·下架 / 删除
- 已发布排在前面，草稿沉底

### 4.2 轮播图管理 `/admin/banners`

- 顶部三卡：总数 / 显示中 / 已隐藏
- 列表带缩略图（加载失败显示占位，不破版）
- 弹窗内实时预览：改一次地址看一眼，不用先存再回列表确认
- 行内动作：编辑 / 显示·隐藏 / 删除

### 4.3 操作日志 `/admin/logs`

- 顶部四卡：总条数 / 今日 / 失败 / 平均耗时
- 筛选：操作人·操作·URI 关键字、模块下拉（`/modules` 动态取）、结果、日期区间
- 失败行浅红底，耗时 > 500ms 标黄
- 弹窗看完整参数，JSON 自动格式化

## 6. 验证步骤

```bash
# 0) 取 token
TOKEN=$(curl -s -X POST http://127.0.0.1:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}' | sed 's/.*"token":"\([^"]*\)".*/\1/')

# 1) 三组统计
curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/admin/announcements/stats
# 期望：total 7 / published 5 / draft 2 / viewTotal 1147

curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/admin/banners/stats
# 期望：total 3 / showing 3 / hidden 0

curl -s -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/admin/logs/stats
# 期望：total ≥15 / todayCount ≥5 / failCount ≥2 / avgCost ≈30

# 2) 切面留痕：新建一条草稿，再看最新日志
curl -s -X POST http://127.0.0.1:8080/api/admin/announcements \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"title":"切面测试","content":"验证 AOP 是否落库","type":"NOTICE","status":0}'
curl -s -H "Authorization: Bearer $TOKEN" "http://127.0.0.1:8080/api/admin/logs?page=1&size=1"
# 期望：最新一条 = 公告管理 / 新增公告 / POST /api/admin/announcements / 成功 / params 含标题

# 3) 失败也记：删一条不存在的公告
curl -s -X DELETE -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/admin/announcements/99999
# 期望：code 404；随后日志里出现同名记录，状态「失败」

# 4) 发布语义：发布时间不被编辑覆盖
curl -s -X PUT .../announcements/8/status -d '{"status":1}'   # publishTime 写入
curl -s -X PUT .../announcements/8        -d '{"title":"改了标题","status":1}'
# 期望：publishTime 仍是第一次发布的时间

# 5) 校验拦截
curl -s -X POST .../announcements -d '{"title":"","content":"x"}'
# 期望：400「公告标题不能为空」
curl -s -X POST .../banners -d '{"title":"坏图","imageUrl":"javascript:alert(1)"}'
# 期望：400「图片地址必须以 / 或 http(s):// 开头」

# 6) 前台免登录 + 浏览量自增
curl -s "http://127.0.0.1:8080/api/announcements?limit=3"
curl -s  http://127.0.0.1:8080/api/announcements/3   # viewCount 比上一次 +1

# 7) 权限隔离：网点管理员访问平台接口
# 期望：403「无权访问该接口」
```

## 7. 本批踩到的坑

| 现象 | 根因 | 修法 |
|---|---|---|
| 日志列表「今日」恒 0 | seed 的日志全在 1 天前 | 补 5 条当天记录（含 2 条失败），统计才有对比 |
| 草稿统计恒 0 | seed 4 条全是已发布 | 补 2 条 `status=0, publish_time=NULL` 的草稿 |
| `@Aspect` 不生效 | `spring-boot-starter-web` 不带 AspectJ 织入器 | pom 加 `spring-boot-starter-aop` |
| 参数序列化抛异常 | 参数里有 `HttpServletRequest` 等不可序列化对象 | 序列化前按类型过滤 |
| 日志表字段超长 | 公告正文几千字全塞进 `params` | 统一截断 2000 字 + 敏感字段脱敏 |

## 8. 已知边界

1. **日志只落库、没做归档**。真实项目要按月分表或转冷存储；
   演示环境数据量小，`idx_create_time` 足够。
2. **没有登录/登出日志**。登录不在 `@OpLog` 覆盖范围内（无登录态），
   如需追溯登录历史应单独建 `login_log`。
3. **参数只记「入参」，不记「改前 / 改后」**。要回答「他把价格从多少改成多少」，
   需要业务侧额外记快照；当前靠 `operation` + `params` 能定位到「改了什么值」。
4. **切面按注解触发**，新增接口忘了加注解就不会有日志。
   可考虑改成「按包路径 + HTTP 方法自动拦截」，但会引入噪音（GET 也记），当前取舍是可读性优先。
