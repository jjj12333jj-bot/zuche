# 01 需求边界与实施计划

> 项目：基于信用风控的微租车平台设计与实现
> 版本：v0.1（设计阶段，无业务代码）
> 原则：可落地、可运行、可答辩；不接真实支付/地图/短信，全部模拟实现；本版本不含在线客服/知识库。

---

## 一、项目定位与核心链路

一句话定位：**一个把"信用分 → 动态押金 → 租赁行为 → 信用分回写"闭环做通的微租车平台**。

主链路（答辩演示主线，必须全通）：

```
浏览车型 → 下单（看信用等级/押金系数/应付押金）
  → 模拟支付（租金 + 押金两笔）
  → 网点交付/用户确认取车 → 在租
  → 申请归还 → 网点确认归还 → 判定是否逾期
  → 押金退还（模拟）→ 订单完成 → 信用分自动更新（写 credit_log）
  → 后台风控效果对比 + 运营看板
```

支线：多网点调车（申请 → 审批 → 归属变更）、收藏/评论/公告/地址、运营分析看板。

**信用风控不是独立模块**，它嵌在：下单时（算押金）、支付时（快照等级）、归还时（判逾期、加减分）、后台（配置与对比）。

## 二、角色与功能边界

| 角色 | 入口 | 本轮实现的功能 | 明确不做 |
|---|---|---|---|
| 普通用户 USER | `/` 前台 | 注册登录、首页（分类/热门/流程/公告）、车辆搜索（关键词/分类/品牌/价格/排序）、车辆详情（多图/折扣/库存/评论）、在线租赁（算租金押金）、我的订单（筛选/支付/取消/确认取车/申请归还/押金退还查询/逾期提示）、收藏、评论、收货地址、公告浏览、个人中心（资料/改密/信用分与变动记录） | 不做发票、保险、优惠券、积分、实名认证 |

| 系统管理员 SYS_ADMIN | `/admin` | 数据看板（KPI/热力图/车型偏好/营收预测）、信用管理（风控效果对比、用户信用列表与调整、等级阈值与押金系数、行为加减分规则）、调度审批、用户/车辆/分类/订单/评论/公告/轮播图/地址/操作日志管理、个人信息与改密 | 不做数据库运维面板、不做多租户 |

## 三、本版本不做（边界外，写清楚是为了答辩防守）

1. **在线客服 / 知识库**：不建表、不写接口、不做页面。任何 `chat / faq / knowledge / ticket` 相关内容都不出现。
2. **真实第三方能力（全部 Mock，且不伪装成真实）**：
   - 支付：`MockPayService` 直接置成功，返回模拟流水号 `MOCK` + 时间戳，页面明确标注"模拟支付"。
   - 地图/定位：不接入任何地图 SDK；网点只用"名称 + 地址文本 + 经纬度字段（仅存不用）"展示，不渲染地图（规避测绘合规问题）。
   - 短信/邮件：注册即成功，验证码环节取消或固定 `123456`（本地开关 `mock.sms.enabled`）。
   - 实名/驾照/OCR：只做字段录入与格式校验，不做真实核验。
3. **技术性过度设计**：不拆微服务、不引 MQ、不强依赖 Redis（缓存只做可选开关）、不做分布式锁/分布式 ID（订单号用时间戳+随机）。
4. **论文文本**：本阶段不产出。

## 五、订单状态机（硬约束，禁止随意跳转）

| 状态码 | 中文 | 允许流转到 | 触发方 |
|---|---|---|---|
| `WAIT_PAY` | 待支付 | `WAIT_PICKUP`（支付成功）、`CANCELLED`（用户取消/超时） | 用户 |
| `WAIT_PICKUP` | 待取车 | `IN_USE`（交付/确认取车）、`CANCELLED`（取车前取消，退款） | 用户 / 网点 |
| `IN_USE` | 已取车/在租 | `WAIT_RETURN`（申请归还）、`OVERDUE`（定时任务超期） | 用户 / 系统 |
| `WAIT_RETURN` | 待归还 | `RETURNED`（网点确认归还） | 网点 |
| `OVERDUE` | 逾期 | `WAIT_RETURN`（申请归还）、`RETURNED`（直接确认归还） | 用户 / 网点 |
| `RETURNED` | 已归还 | `COMPLETED`（押金处理完成） | 网点 |
| `COMPLETED` | 已完成 | — 终态 | — |
| `CANCELLED` | 已取消 | — 终态 | — |

实现方式：`OrderStatus` 枚举 + `OrderStateMachine` 工具类维护 `Map<状态, Set<允许目标>>`，每次变更前 `assertCanTransfer(from, to)`，非法流转抛 `BusinessException("订单状态不允许该操作")`。所有状态变更集中在 `OrderService` 一处，网点端与用户端复用同一方法（保证幂等：状态不符直接返回业务异常，不重复扣库存/加分）。

**库存一致性**：下单即锁库存（`vehicle.stock - quantity`，`stock >= quantity` 才允许）；`CANCELLED` 回补；`COMPLETED` 不回补（车已还回，在 `confirmReturn` 时回补）。这条写进注释，答辩常被问。

## 六、信用分与动态押金规则（核心特色）

### 6.1 分值自洽原则

> **credit_score = clamp(100 + Σ credit_log.score_change, 0, 150)**

不搞"事件加分 + 定时重算"双轨（会漂移、答辩讲不清）。分数恒等于 100 加全部日志增量之和，**任何一次变动都有日志、日志可回放、分数可复算**。等级由分数落在 `credit_rule` 的哪个区间决定。

### 6.2 等级与押金系数（credit_rule，可配置）

| level_code | 等级 | 分数区间 | 押金系数 |
|---|---|---|---|
| `EXCELLENT` | 优秀 | 120 ~ 150 | 0.80 |
| `GOOD` | 良好 | 100 ~ 119 | 0.90 |
| `NORMAL` | 一般 | 80 ~ 99 | 1.00 |
| `WATCH` | 待观察 | 0 ~ 79 | 1.20 |

区间必须在后台校验"连续不重叠、覆盖 0~150"，保存时校验，防止配出空洞。

### 6.3 行为加减分（credit_action_rule，可配置）

| action_code | 场景 | 默认分值 | 幂等键 |
|---|---|---|---|
| `ORDER_FINISH` | 订单完成 | +2 | order_id |
| `ON_TIME_RETURN` | 按时归还（未逾期） | +5 | order_id |
| `OVERDUE` | 逾期（每逾期 1 天，最多 7 次） | -3 | order_id + day |
| `OVERDUE_RETURN` | 逾期后归还 | -5 | order_id |
| `CANCEL_PAID` | 取消已支付订单 | -3 | order_id |
| `ADMIN_ADJUST` | 管理员手工调整 | 手填 | 无需 |

幂等：`credit_log` 上建唯一索引 `uk_log_dedup(order_id, action_code, dedup_key)`，重复事件插入失败即忽略 —— 定时任务跑多次不会重复扣分。

### 6.4 押金计算

```
rentAmount    = dayPrice × rentDays × quantity × discountRate   // 折扣默认 1.00
depositAmount = vehicle.deposit × creditRule.depositCoefficient  // 按当前分数取系数
totalAmount   = rentAmount + depositAmount
```

下单时把 `credit_score / credit_level / deposit_coefficient / day_price / discount_rate` 全部**快照**进 `lease_order`，之后用户分数变了也不影响已有订单（答辩点：为什么快照）。

### 6.5 风控效果对比（后台图表，全部 SQL 聚合）

- 各信用等级订单量（`group by credit_level_snapshot`）
- 各等级逾期率（`sum(overdue_days>0)/count`）
- 押金减免金额（`Σ(vehicle.deposit - deposit_amount)`，只算系数<1 的）
- 各等级平均客单价、取消率

### 6.6 逾期判定

`@Scheduled` 每小时扫一次：`status IN ('IN_USE') AND end_date < today` → 置 `OVERDUE`，按天数写扣分日志；订单详情/列表返回"已逾期 N 天，预计违约金 X"。违约金 `late_fee = day_price × overdueDays × 1.5`，在确认归还时结算。

## 七、阶段计划（小步交付，每阶段可运行、可演示）

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **S0 骨架** | 前后端工程、pom、yml、统一返回/异常、JWT、角色拦截、Knife4j、SQL schema + seed | `mvn -q package` 通过；`npm run build` 通过；`/doc.html` 可开；空接口返回统一结构 |
| **S1 基础域** | 用户/角色/登录注册/JWT、网点、分类、车辆 CRUD + 前台列表/详情、首页、公告、轮播图 | 三种角色能登录并看到各自菜单；车辆列表筛选排序生效 |
| **S2 租赁主流程** | 下单（算押金）、模拟支付、库存、状态机、取车、归还、完成、订单列表筛选 | 走通"下单→支付→取车→归还→完成"，非法状态跳转被拒 |
| **S3 信用风控** | credit_rule / credit_action_rule / credit_log、事件触发、信用中心页、手工调整、风控对比图 | 完成一单后分数与日志一致；手工调整有原因、有日志；对比图有数 |
| **S4 网点端** | 网点概览、本网点车辆、订单交付/归还/押金、调车申请 | 网点只能看本网点数据；调车申请状态正确 |
| **S5 管理端** | 看板 4 张图、调度审批、用户/订单/评论/公告/轮播/地址/日志管理 | 图表数据来自库；审批通过后车辆归属变更 |
| **S6 收尾** | seed 数据（含 30 天历史订单，供预测用）、Swagger 注解补齐、构建验证、启动说明 | 一键初始化后看板/预测/热力图都有数；README 可复现 |
